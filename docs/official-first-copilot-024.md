# Official-first review: Copilot alpha.24 against DSH 0.1.6-alpha.1

## Scope and evidence

This is a read-only source/contract comparison, not live endpoint or official-only replacement-runtime acceptance. It changes no immutable release, installed runtime, settings or credentials.

- Official target: **DSH `0.1.6-alpha.1`**, commit [`0a15e36e7f82b6ed45af6fa9759f29b40dcd965d`](https://github.com/deepseek-ai/deepseek-harness/commit/0a15e36e7f82b6ed45af6fa9759f29b40dcd965d).
- Plugin: **`dsh-github-copilot@0.4.0-alpha.24`**, published commit [`e49bf7c9307cf22dd9ea720bed8750101fc986ed`](https://github.com/cloga/dsh-github-copilot/commit/e49bf7c9307cf22dd9ea720bed8750101fc986ed), qualified tree `96cea3ac3377b6eee5467bf6f668822f66d3f811`.
- Exact source trees and [official release notes](https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.1.6-alpha.1) were reviewed. Reasoning UI improvements, body-only subagent notices, async serial `agent/created`, image-offload events and Session API changes are relevant integration facts, not proof of account-discovery, fixed-role or search-router equivalence.

**Conclusion:** prefer official OAuth, credential persistence/refresh, normal model transport, child-agent execution/model-selection primitives, provider transport, Session ownership and replay. The plugin already delegates most of these. Full companion replacement parity is not established. No complete shipped customization is proven safe for unconditional deletion. Some target-specific legacy paths and an SDK bridge merit future pruning only after the conditions below are met.

## Compact decisions

`Full` applies only to the named primitive. `Partial` identifies a concrete gap; `unverified` does not mean absent. File/line references below resolve through the fixed-commit evidence links following the table. These are source decisions, not claims of paid-provider or official-only runtime acceptance.

## Migration and retirement gates

1. Apply the [mandatory checklist](local-core-desktop-copilot.md#official-first-upgrade-checklist) in each upgrade Issue/PR; refresh exact-target decisions, not a permanent retain table.
2. Prefer official composition for ordinary OAuth/chat or selectable child models. Do not enable a managed route or dedicated roles simply because available. **Where the retained requirements above apply**, keep only the documented gaps until replacement is proven; this review does not invent new user requirements.
3. Qualify replacements with boundary tests and actual packaged UI/runtime acceptance. Alpha.24 CI and paired fork acceptance are not official-only replacement or real model/search performance evidence.
4. Explicitly migrate route IDs, current/default/pending/historical Session selections, legacy settings/journals, roles and search policy. Preserve user-owned configuration/history; do not silently erase role projections or reinterpret paid-fallback consent. Remove obsolete code/path tests only after replacement is verified, preserving user-visible requirement acceptance.
5. Retire code through a new reviewed release. Never rewrite immutable alpha.24 or activate/restart Desktop as part of source parity review.

**Still unverified:** live account/model capability parity, full official-only composition replacement, resolved SDK identity across all admitted older baselines and safe deletion of legacy records/history. **Already delegated:** official OAuth/records, normal model adapter/SDK, native subagent backend, official DeepSeek transport and Session/replay/attachment ownership. **Unconditionally redundant whole shipped feature:** none established. See the separate [Desktop decisions](official-first-desktop-016.md) and [current paired evidence boundaries](local-core-desktop-copilot.md#authoritative-baseline).
